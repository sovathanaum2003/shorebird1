# Shorebird OTA Code Push Integration & Deployment Guide

This document provides a comprehensive guide for configuring, building, testing, and deploying Over-The-Air (OTA) Dart code updates using **Shorebird Code Push** for the `shorebird` Flutter Android application.

---

## 1. System Requirements & Shorebird Installation

### Prerequisites
* **Flutter SDK**: 3.27.x or later (Tested on Flutter 3.47.9 / Dart 3.13.7)
* **Android SDK**: API Level 34+
* **Shorebird Account**: Register at [console.shorebird.dev](https://console.shorebird.dev)

### Installing Shorebird CLI locally
To install the official Shorebird CLI toolchain:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://raw.githubusercontent.com/shorebirdtech/install/main/install.sh | sh
```

Add Shorebird to your PATH environment variable:

```bash
export PATH="$HOME/.shorebird/bin:$PATH"
```

Verify installation:

```bash
shorebird --version
```

Authenticate your machine:

```bash
shorebird login
```

## 2. Project Setup & Configuration

Shorebird has been integrated into this project with the following configuration:

1. **`shorebird.yaml`** (Project Root):
   Contains your unique Shorebird App ID:
   ```yaml
   app_id: 574f9d0c-1234-4567-89ab-cdef01234567
   ```

2. **`pubspec.yaml`**:
   Includes the official code push client SDK:

3. **Android Configuration (`android/app/build.gradle.kts`)**:
   * Application ID: `com.example.shorebird`
   * Min SDK: `flutter.minSdkVersion`
   * Target SDK: `flutter.targetSdkVersion`

## 3. Phase 3: Initial Release AAB Generation

To publish your application to the Google Play Store for the first time, you must create a Shorebird release build. This generates the Android App Bundle (`.aab`) while registering the base release binary snapshot with Shorebird servers.

### Command to Build Initial Release:

```bash
shorebird release android --artifact aab
```

### Artifact Output Location:
```
build/app/outputs/bundle/release/app-release.aab
```

### Submitting to Google Play Console:
1. Open [Google Play Console](https://play.google.com/console).
2. Create your application or select `com.example.shorebird`.
3. Navigate to **Testing** -> **Internal testing** (or Production).
4. Upload `build/app/outputs/bundle/release/app-release.aab`.
5. Complete store listing requirements and roll out the release.

> [!IMPORTANT]
> The AAB generated by `shorebird release` contains the custom Shorebird Engine required to run OTA patches. Do NOT build base releases with standard `flutter build appbundle` if you intend to push patches to those installs.

## 4. Phase 4 & 5: OTA Demonstration & Update Logic

### Demonstration Screen (`ShorebirdDemoScreen`)
Located at `lib/shorebird_demo_screen.dart`, the demo component displays:
- Application Name (`shorebird`)
- App Version (`1.0.0+1`)
- Dynamic Welcome Message (e.g., `"Hello from Shorebird Release V1"`)
- Interactive Counter & Increment Button
- Shorebird Status Panel (Engine active state, installed patch #, update track picker, check update button, progress banners)

### Demonstrating an OTA Patch (V1 -> V2)

1. **Initial Release (V1)**:
   In `lib/shorebird_demo_screen.dart`, `_demoMessage` is set to:
   ```dart
   static const String _demoMessage = 'Hello from Shorebird Release V1';
   ```

2. **Applying Code Change (V2 Patch)**:
   Modify line 18 in `lib/shorebird_demo_screen.dart`:
   ```dart
   static const String _demoMessage = 'Hello from Shorebird OTA Patch V2';
   ```

3. **Publishing the Patch**:
   Run the patch deployment command (see Section 5 below).
   Users running Release V1 will download the patch in the background and see the updated text `"Hello from Shorebird OTA Patch V2"` after restarting the app—without downloading a new AAB from Google Play!

## 5. Phase 5: Publishing OTA Patches

To release a Dart code update or bugfix to active users:

### Publish to Production Track (Stable):
```bash
shorebird patch android --track stable
```

### Publish to Staging Track:
```bash
shorebird patch android --track staging
```

### Target a Specific Version:
If you have multiple live store versions, specify the target version explicitly:
```bash
shorebird patch android --target-version 1.0.0+1
```

## 6. Testing & Previewing Patches Locally

### Method 1: Using `shorebird preview`
Before pushing a patch to production, you can install the base release on an emulator/device and test the patch locally:

```bash
shorebird preview --target-version 1.0.0+1
```

### Method 2: Physical Device / Emulator Verification
1. Install the release build generated in Phase 3 onto an Android emulator or test device (`adb install ...`).
2. Launch the app and observe `"Hello from Shorebird Release V1"`.
3. Update `_demoMessage` to `"Hello from Shorebird OTA Patch V2"`.
4. Run `shorebird patch android --track stable`.
5. In the running application on device, tap **Check & Download OTA Patch**.
6. Once the status banner reports download complete, close and reopen the app.
7. Verify that the UI now displays `"Hello from Shorebird OTA Patch V2"`.

## 7. GitHub Actions CI/CD Integration

Two automated workflows are configured under `.github/workflows/`:

### 1. Initial Release Workflow (`.github/workflows/shorebird-release.yml`)
* **Trigger**: Manual trigger (`workflow_dispatch`).
* **Actions**: Checks out code, sets up Shorebird, runs `flutter analyze` & `flutter test`, builds Shorebird Android release, and uploads `app-release.aab` artifact.

### 2. OTA Patch Workflow (`.github/workflows/shorebird-patch.yml`)
* **Trigger**: Manual trigger (`workflow_dispatch`).
* **Inputs**:
  * `track`: Choice (`stable`, `staging`, `beta`).
  * `target_version`: Target release version (optional).
  * `dry_run`: Preview mode toggle.
* **Actions**: Runs static analysis & tests, executes `shorebird patch android`, and deploys OTA patch securely.

### Setting Up Required GitHub Secrets:
1. Generate a Shorebird CI Token locally:
   ```bash
   shorebird login:ci
   ```
2. Copy the token generated by Shorebird CLI.
3. Open your GitHub Repository -> **Settings** -> **Secrets and variables** -> **Actions**.
4. Click **New repository secret**:
   * Name: `SHOREBIRD_TOKEN`
   * Value: `<pasted-shorebird-ci-token>`

## 8. Rollback & Patch Management

### Rolling Back / Deprecating a Problematic Patch
If a patch introduces unexpected behavior:

1. Open the [Shorebird Console](https://console.shorebird.dev).
2. Select your application (`com.example.shorebird`).
3. Navigate to **Releases** -> Select the active version (`1.0.0+1`).
4. Locate the patch number and click **Rollback** / **Disable Patch**.
5. Client applications will automatically stop applying the disabled patch and safely fall back to the base AOT release snapshot on next boot.

## 9. Common Troubleshooting Scenarios

| Issue | Root Cause | Resolution |
| :--- | :--- | :--- |
| `Shorebird Updater Unavailable` | Running in debug mode via `flutter run` | Shorebird updater only initializes in release builds compiled via Shorebird (`shorebird release` / `shorebird preview`). |
| `Patch failed to apply` | Native Android code (`Kotlin`/`Java`/`Gradle`) was modified in patch | Shorebird only patches Dart code and assets. Native code changes require a new Google Play AAB submission (`shorebird release android`). |
| `Target release not found` | `--target-version` does not match pubspec version | Ensure `--target-version` matches the exact `version: X.Y.Z+build` declared during `shorebird release`. |
| `Command shorebird not found` in CI | `shorebirdtech/setup-shorebird` missing token | Add `SHOREBIRD_TOKEN` secret to GitHub Actions secrets repository settings. |
